# MASTERMIND working agreement

## Course intent
SLOP4408, MASTERMIND: The Art of the Impossible Heist, is an elite fictional SlopU academy. Twelve weeks develop one operation, Glass Crown, at the invented Grand Reserve. Serious briefings and precise teaching lead; restrained institutional satire is secondary. Do not imitate television characters or use real intrusion techniques.

## Fixed platform
Read README.md before structural work. Keep Astro, strict TypeScript, SlopU branding, the four collection schemas, generated API, build integrations, deployment workflow and secret checks. Keep suffix 408. Use Node 24 / pnpm 11.9.0 through mise in WSL. Respect the repository base path in every URL.

## Educational promises
- Each week teaches a distinct capability, supplies sufficient preparation, produces a named dossier artefact and explains where it is reused.
- Assessment is fieldwork 10%, individual dossier 20%, pair revision 25%, group capstone 45%. Endings never determine academic marks.
- Separate evidence, claims and assumptions. A later authoritative document may supersede an earlier rule but must not silently rewrite history.
- Week 7 preserves Version 1 and creates an explained Version 2. All weeks and samples remain directly accessible.
- Objective feedback explains the fictional rule. Open-ended reflection receives exemplars, not fabricated automated grades.

## Implementation and acceptance
- Static accessible HTML first; focused TypeScript enhancement. No accounts, backend, live AI, real submissions or arbitrary code execution.
- Support keyboard, reduced motion, phone layouts and static worksheets. Test 1920x1080 and 390x844.
- Validate versioned imports before replacing state. Preserve work on errors; offer export if saving fails. Render imported text as text.
- Keep curriculum facts in content records and simulation rules in typed data. Test behaviour and built content.
- Work in complete reviewable slices. Record actual decisions and failures in docs/DECISIONS.md and improve the relevant rule or test.
- Run pnpm check and pnpm check:evidence. Browser review is separate. Deployment does not prove the check job passed.
- PROCESS.md is the student's own account. Organise evidence and edit supplied wording; never invent first-person decisions, human testing, citations or acceptance.

## Authorship

## Rules added after rendered review
- Check contrast in a real browser: the static build cannot measure rendered colours. Keep brand tokens intact and use darker bronze or ink for small text.
- Check the bounds of content inside clipped containers, not only document overflow. Inspect every deck slide at both viewports.
- A storage failure must still allow a backup on the current page. Test the downloaded file, not only the warning message.
- A keyboard journey must actually navigate and enter answers with keyboard events. Keep the theme search and menu usable, with static course navigation when JavaScript is absent.
