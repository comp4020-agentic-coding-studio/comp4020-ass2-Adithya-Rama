# Challenge the System

Week 7 · MASTERMIND

A recognised identity is not a permission.

```notes
Open with the observer role selected. Ask whether knowing who someone is establishes what they may do. Accept a concrete counterexample.
```

## The unexpected result

An observer can certify the archive.

A registrar cannot.

Both results contradict the mandate.

```notes
Show the initial faulty matrix: observer has read, service and certify; other roles have read only. Distinguish an unauthorised success from a legitimate operation wrongly denied.
```

<DeckNav slide={2} total={14} />

---

## State the contract first

Everyone may read.

Technicians may service the cart.

Registrars may certify the archive.

```notes
Have students paraphrase the rule. No role may infer authority from a button being available. The contract determines expected results.
```

<DeckNav slide={3} total={14} />

---

## Three parts of a request

**Subject:** observer

**Action:** certify

**Object:** archive

```notes
Ask which part changes when the same person requests read instead of certify. Explain that the simplified model fixes an object for each action; real systems may need finer distinctions.
```

<DeckNav slide={4} total={14} />

## Identity and authority

Identity answers **who**.

Permission answers **may they do this**.

The second question must still be asked.

```notes
Avoid treating an account or badge as universal authority. All examples remain in the local fictional simulator.
```

<DeckNav slide={5} total={14} />

## Predict the matrix

| Role | Read | Service | Certify |
| --- | --- | --- | --- |
| Observer | Allow | Deny | Deny |
| Technician | Allow | Allow | Deny |

```notes
Give pairs two minutes to predict all nine cells before revealing the completed matrix. Ask one student to justify a positive case and another a negative case.
```

## A reproducible test

Observer → certify archive

**Expected:** deny

**Observed before repair:** allow

```notes
A useful failure record identifies the case and the expected result. It should not simply say that the application is insecure.
```

## Repair the actual policy

Remove observer service and certification.

Restore technician service.

Restore registrar certification.

```notes
The complete repair changes four cells. Removing only observer certification leaves both excess authority and missing legitimate capability.
```

## Denying everything fails too

No unauthorised operation succeeds.

But nobody can do their job.

Useful access is part of the requirement.

```notes
Ask what a test suite containing only forbidden cases would miss. Connect the example to why regression tests must include positive cases.
```

<DeckNav slide={9} total={14} />

## Recheck all nine cases

The forbidden action now fails.

The required action still succeeds.

Unrelated rights remain correct.

```notes
Students compare before/after matrices. Require all nine expectations, not a screenshot of one passing button.
```

## A mandate changes

A published maintenance hold suspends service.

Read access remains.

Registrar certification remains.

```notes
This is new authoritative material, not a secret trick or evidence the earlier matrix was wrong. Preserve the earlier matrix with its original mandate.
```
